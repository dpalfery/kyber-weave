## 1. Problem and goal

### 1.1 Problem

The `kyber-weave` MCP server — and with it `agent_coding_standards`, the tool that hands an agent the coding standards it must follow — reaches the `conductor` on no target, and reaches *no* agent at all on five of the thirteen. Today's per-target reality, verified in this checkout:

| Target | Mechanism | Who gets kyber-weave |
|---|---|---|
| Factory | per-droid `mcpServers` whitelist derived from `products/kyber-squad/mcp.json` | every agent except `conductor` |
| Claude | `mcp__codegraph__*`, `mcp__kyber-weave__*`, `mcp__context7__*` wildcards in the `tools` allow-list | every agent except `conductor` |
| ZCode | enumerated `mcp__<server>__<tool>` names from `toolchain.yml` `required-mcp-tools` | every agent except `conductor` |
| Devin | the same enumerated names in `allowed-tools` | every agent except `conductor` |
| Copilot | each agent's own `copilot-tools` frontmatter (validated against `CopilotToolCatalog.RequiredCapabilities`) | every agent except `conductor` (whose `copilot-tools` names no MCP entry) |
| OpenCode | server-scoped permission key `kyber-weave_*` | every agent except `conductor` |
| Pi | per-agent source-declared overlay (`pi-extensions`/`pi-tools`), live-verified for `research-agent` + context7 only | `research-agent` only |
| Command Code | none — "MCP tools reach a subagent only when named in tools; Squad names none" | nobody |
| Cursor, Codex, Kilo, Warp, Antigravity | no MCP surface in the renderer | nobody |

Every MCP-granting renderer excludes the agent whose capability profile id is `orchestrator` under a predicate triplicated verbatim across `FactoryRenderer.GrantsMcp`, `ZCodeRenderer.GrantsMcp`, and `DevinRenderer.GrantsMcp` (with inline equivalents in `ClaudeRenderer` and `OpenCodeRenderer`), justified as "a role that only routes work has no use for documentation or code-graph lookups" (`ZCodeRenderer.DescribeWithheldMcp`, echoed in `docs/kyber-squad/architecture.md` and the requirements matrix). The duplication was reported as a parked finding on PR #486 because that plan's D9 forbade editing sibling renderers; this work touches all of them, so the consolidation is in scope.

The owner has overridden both halves with a stated quality reason:

> "all harnesses should reflect what we did for factory, one of the kyber-weave mcp tools is get my coding standards. that is critical to quality every agent including conductor shold have kyber-weave-weave mcp"

### 1.2 Goal

Acceptance criteria:

1. On every target that can express a per-agent MCP grant (Factory, Claude, ZCode, Copilot, OpenCode, Pi, Command Code, Kilo, and Antigravity), every agent whose capability profile resolves and allows `filesystem.read` is granted the `kyber-weave` server on the file that target renders, **`conductor` included wherever that target renders a conductor file**; on the shipped squad that is all 24 agents. **Two targets are qualified because their `conductor` is a lowered skill with no grant surface at all, so the rule is structurally inexpressible there rather than narrow.** On **Devin** (D16) the per-agent grant surface exists only on subagent profiles — the primary-to-skill lowering emits a `SKILL.md` that carries no tool keys, so the `conductor`'s Devin grant is structurally inexpressible and its reach there is the main Devin Local session, whose `mcp_config.json` the operator already owns. On **Pi** the lowered skill carries no `tools` or `extensions`, so the same reading applies, the skill's degradation record names `kyber-weave` and the reason, and the derived overlay reaches every entitled subagent file instead. The parity guard pins both absences by name. *(Amended 2026-10-31: the Kilo and Antigravity parenthetical lost its "evidence-gated" qualifier because both landed a probed per-agent grant, and **Pi joined Devin in the structural qualifier** — the criterion previously listed Pi among the targets that grant the `conductor`, which no Pi surface can do. D16 and H2 were already correct on Devin and are unchanged.)*
2. On targets that cannot express a per-agent grant (Cursor, Codex, Warp), the governed docs state the boundary plainly with vendor citations, the runbook tells the user how to wire the server at session level, and no renderer invents an unenforceable field.
3. `codegraph` and `context7` keep the pure-orchestrator carve-out; no existing grant on any target narrows.
4. The entitlement predicate exists once, in the shared home, with a contract test that computes expectations from the loaded `SquadSource` and pins the rule across every granting renderer.
5. The reversal is recorded as a deliberate decision with the owner's reason — a new ADR plus in-place amendments — never as a silent removal.
6. The `permission-not-expressible` stream stays honest: a granted agent records no MCP-withholding claim anywhere; a withholding names exactly what is withheld and why.
7. All squad contract/canonical-content tests pass, `docs validate` and `docs drift` pass, and no `products/kyber-squad/**` file changes beyond the one-line `conductor.md` `copilot-tools` entry.

## GAPS

- **G1 (closed 2026-10-31, gates T4):** The Pi spelling and the adapter's server-configuration mechanism are established. The emitted entries are `ext:pi-mcp-adapter/mcp__kyber_weave__<tool>`: the adapter's deferred-tool surface names a tool `mcp__<namespace>__<tool>` and maps the server name's hyphen to an underscore before any other character, established by executing the package's published naming code over the roster and corroborated by Pi's own MCP documentation plus a live MCP `tools/list` (the adapter's `doctor` reported `kyber-weave: ok, 8 tools`). The naming arrived in `pi-mcp-adapter` 6.0.0 and 7.0.0 is the supported target; 5.x registers no per-tool names at all and would spell them `kyber-weave_<tool>`, which is why an operator there keeps the `mcp` proxy entry and loses only the enumerable names. Server configuration is the operator's `.mcp.json` (or a user-global equivalent), and a project-scoped entry needs a first-use trust approval. What remains an owner probe is only the in-session tool listing; the spelling is not inferred, and D8 was corrected from the hyphenated form it originally recorded.
- **G2 (closed 2026-10-31, gates T6):** The package read landed against `@kilocode/cli` 7.8.18 (`Kilo-Org/kilocode` tag `v7.8.18`). Its agent-file loader parses every frontmatter key into the agent config and validates the result against the agent schema; `permission` is a first-class key with `ask`, `allow`, `deny`, or null values and a catch-all map for arbitrary keys. MCP tools are gated by that same map under `{server}_{tool}`, with the server name sanitized only for characters outside `[a-zA-Z0-9_-]`, so the hyphen survives and the wildcard is `kyber-weave_*` — confirmed by executing Kilo's own matcher: `kyber-weave_docs_status` matches, `kyber_weave_docs_status` does not.
