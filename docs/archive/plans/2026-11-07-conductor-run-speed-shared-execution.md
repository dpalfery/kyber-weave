## Problem and goal

The parent design's measured run showed bug-crusher spending **2h14m on a 4-source-file fix and never reaching a review verdict**. Two of its causes: it carries its own partial copy of the worker rules — `bug-crusher/SKILL.md` §5's execution step duplicates the conductor's execution contract, so the two copies drift — and its roster is too narrow for the escalation it is told to perform: `bug-crusher.md:15` allows only the investigator, `docs-dev` and the two review seats, so as rendered for Claude Code the escalated path cannot start `architect`, `test-dev`, developers or `code-reviewer`, and even its shell-less run-start dispatch has to be escalated rather than run.

The goal of this slice (the parent's fix 2): **one copy of the worker execution contract, in a canonical skill both entry points load** (D20), so bug-crusher stops keeping a second copy and stops editing plan status itself; **the delegate list widened** so the escalated path can actually start the specialists; and **the `/conductor` skill's live load treated as a post-merge check**, because this fix relies on it but the check validates a deployment that only exists after merge — the live session runs once a release carries the slice, recorded in the open todo `docs/todo/claude-conductor-live-verification.md` (D55), which this slice leaves open.
