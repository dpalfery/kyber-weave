# KyberDash: session list cost column is `—` and Claude/Codex/Copilot models have no price (issue #186)

**Status: Archived 2026-09-30.** Implementation complete on branch `fix/issue-186-cost-pricing` ([PR #225](https://github.com/dpalfery/kyber-weave/pull/225)); final review council APPROVE. Implementation authority was granted 2026-09-30. Decisions Q1–Q4 are resolved
(U8–U11), and the user's approve-and-execute instruction is recorded as U12.

Fixes [issue #186](https://github.com/dpalfery/kyber-weave/issues/186) (S1, labels `bug`,
`in-progress`). The 2026-09-30 web dashboard audit (kyberdash 0.1.7-rc.15) recorded: all ~450
session rows show `—` in the right-hand column; the cost tile is `—` for Claude, Codex and
Copilot because `claude-sonnet-5-5`, `claude-opus-5` and `gpt-6-luna` have no published rate;
only ZCode, OpenCode, Cursor and Antigravity price; "the rate table is dated 2026-08-06 and is
Copilot billing only".

## Problem and goal

Two independent defects produce the symptom:

- **Defect A (display plumbing).** The session list reads a cost field that no writer produces,
  so every row renders `—` even for sessions whose cost is priced.
- **Defect B (pricing).** Records from Claude Code, Codex and Copilot are never priced from a
  published rate, so their session cost stays `no_rate` even when the model is in the bundled
  rate snapshot.

Goal: the session list shows the same cost answer the session's cost tile shows — a figure
when priced, the reason in words when not (R5.4). Claude Code and Codex turns are priced from
the bundled LiteLLM snapshot under R5.3 applicability scoping, and Copilot turns are priced from
a Copilot credits table. A model with no published rate stays honestly unpriced, and the user
can price it through the existing `priceOverrides` / `modelAliases` config.

## Investigation findings

Verified 2026-09-30 against this checkout through CodeGraph (`codegraph_explore`, index present)
and direct reads. `docs_explore` supplied the governed cost contract.

### Defect A: the list reads a field nothing writes (confirmed)

- The writer: `buildSessionRow` stores `summary.cost` as a `CostBlock`
  `{basis, status, value?, currency?, byModel?}`, falling back to `{basis:'unknown', status:'no_rate'}` when `sumCosts`
  refuses (`dash/src/canon/sessions.ts:484`, `:518`).
- The reader: `KyberBridge.listSessions` maps `cost_usd: summ.cost?.usd ?? null`
  (`dash/src/server/bridge.ts:922`) under a `ParsedSummary.cost` type of `{usd, basis, status}`
  (`bridge.ts:147-151`). No canonical writer emits `usd`, so `cost_usd` is always `null`.
- The renderer: `AgentSessionRow` renders `costUsd != null ? usd(costUsd) : '—'`
  (`dash/web/src/components/ContextExplorer.tsx:86`, `:158-161`).
- The tests are green on a shape the writer never produces. `kyber-bridge.test.ts:481`
  (`cost_usd` 0.05) and `kyber-api.test.ts:43`, `:164`, `:450`, `:526` seed the legacy Python
  pipeline shape `{usd, basis:'published_rates', status:'ok'}`. `ContextExplorer.test.tsx:68`, `:147`
  and `analysis/session-dashboard.test.tsx:51` do the same.
- **The cost tile** is `SessionCostPanel` (`dash/web/src/components/SessionCostPanel.tsx:193`).
  It reads `session.summary.cost` through `extractCostBlocks`/`normalizeCostBlock` (`:85-191`) and
  renders words through `formatCostFigure` (`:61-80`). The tile is therefore correct in shape: it
  shows "no published rate" for Claude, Codex and Copilot because of Defect B, not Defect A.
- **The "token" half of the column title is not a separate defect.** `AgentSessionRow` has no
  column header and no token cell. Its right-hand cells are turn count (`:154-156`), cost
  (`:159-161`) and time. The issue title's "cost/token" names the one cost cell.
  - Latent finding, not in scope: `SessionSummary.total_input` is typed `number | null`
    (`bridge.ts:97`), but the writer may store a `NotMeasurable` object there
    (`sessions.ts:512`, `unavailableFor(measurability, 'token_usage') ?? totals.input`). The row
    does not render it today, so nothing is visibly wrong. Report it as a follow-up if a token
    column is ever added.

### Defect B: nothing prices Claude, Codex or Copilot turns (confirmed; root cause sharper than intake)

- `createCostBlock` / `priceWithTable` (`dash/src/canon/cost.ts:150-210`) have **no production
  caller**. Only tests call them (`cost.test.ts`, `cost.scoping.test.ts`, `data-handling.test.ts`).
  The OTLP adapter base leaves cost as a placeholder "for the cost engine (task 4)". That step
  was never wired (`dash/src/canon/adapters/base.ts`, `baseRecord` in `canon/adapters/copilot.ts:588-607`).
- File-sourced records get their cost from `costBlockFor` (`dash/src/synth/synth.ts:306-317`).
  A non-zero upstream `costUSD` becomes `published` (if `costIsEstimated`) or `harness`.
  **Zero becomes `{basis:'unknown', status:'no_rate'}`.**
- **The Claude reader always emits `costUSD: 0`** with the comment "Cost is derived downstream
  from the counters and the rate table" (`dash/src/synth/readers/claude.ts:148-151`). No downstream
  step exists. So every Claude file-sourced turn is unpriced **whatever the model**. This explains
  why the audit lists `claude-opus-5` as unpriced although the snapshot carries it
  (`litellm-snapshot.json` keys `claude-opus-5`, `claude-sonnet-5`, `gpt-5.6-luna`; there is no
  `claude-sonnet-5-5` and no `gpt-6-luna` key).
- OTLP records are priced only from a harness-reported `cost_usd`
  (`dash/src/otel/service.ts:74-77`). Otherwise they are `{unknown,no_rate}`.
- **Basis-mix refusal hides partial pricing.** `buildSessionRow` sums **all** records
  (`sessions.ts:484`, `records.map(r => r.cost)`), including non-turn spans. `sumCosts` refuses
  mixed bases (`cost.ts:265-275`), and `sessions.ts:518` then silently writes `{unknown,no_rate}`,
  dropping the `COST_BASIS_MISMATCH` problem. So one priced turn (`harness` or `published`) plus
  any `unknown` block (a tool span, an unpriced turn) turns the whole session into "no published
  rate". The session is never `partial`.
- **Latent R5.3 hazard (Copilot).** The upstream Copilot provider parser prices through LiteLLM's
  `calculateCost` and labels measured-token figures `costIsEstimated: false`
  (`dash/src/providers/copilot.ts:997-1013`), which `costBlockFor` turns into `basis:'harness'`.
  Today this prices nothing, because Copilot's models are not in the snapshot. But if a Copilot
  model's API rate lands in the snapshot, Copilot turns would be priced at API rates and
  mislabelled as harness-reported. That is the exact R5.3 failure recorded in
  `docs/reference/kyberdash-rationale.md` ("R5.3 — Rate-table scoping failure").
- **The "rate table dated 2026-08-06, Copilot billing only"** is display metadata, not a pricing
  table: `getMeta()` returns `{credit_usd: 0.01, source: GitHub models-and-pricing, retrieved:
  '2026-08-06'}` (`bridge.ts:2233-2251`), optionally overridden by `ratesPath`. No Copilot rate
  table exists in the pricing path (design step 5 adds one).
- `priceWithTable` prices `measuredInput × inputRate` (`cost.ts:175`). Cache reads and writes are
  charged at the full input rate, so it cannot express LiteLLM's cache rates. The Claude/Codex step
  must price through `pricing/models.ts` (`getModelCosts` / `calculateCost`, `models.ts:990`,
  `:1187`), which is cache-aware and already honours `priceOverrides`, `modelAliases` and
  `flatRateModels`, wrapped in an R5.3 scope check.
- Harness ids are normalized through `dash/src/canon/measurability.ts`
  (`claude-cli`/`claude-desktop`/`claude-unclassified` → `claude-code`;
  `codex-cli`/`codex-desktop`/`codex-unclassified` → `codex`; `copilot-*` → `copilot`, `:149-160`).
  Applicability must compare normalized ids.
- Store: `SCHEMA_VERSION = 14` (`dash/src/canon/store.ts:81`). `docs/dash/architecture.md` still
  says "currently at version 13", a prose drift to correct at closeout. Derived tables are rebuilt
  wholesale on every projection (`dash/src/canon/projection.ts:19-26`).

### External rate facts (research-agent, retrieved 2026-09-30)

All three models the audit names **do have published rates**. The defect is a stale bundled
snapshot plus the missing pricing step, not an absence of published rates. Rates are USD per 1M
tokens, and none is inferred from a sibling model.

|---|---|---|---|---|---|---|
| `claude-sonnet-5-5` | [Anthropic pricing](https://platform.claude.com/docs/en/about-claude/pricing) | 2.00 | 0.20 | 2.50 (1h: 4.00) | 10.00 | Flat across the 1M window |
| `claude-opus-5` | same | 5.00 | 0.50 | 6.25 (1h: 10.00) | 25.00 | Flat |

  `claude-opus-5` `[5e-6, 2.5e-5, 6.25e-6, 5e-7, 2]` and `claude-sonnet-5` `[2e-6, 1e-5, 2.5e-6,
  2e-7, null]`. Both agree with Anthropic's page. It has no `claude-sonnet-5-5` and no
  `gpt-6-luna`.
- **Upstream LiteLLM.** `claude-sonnet-5-5` was added by
  [BerriAI/litellm PR #43586](https://github.com/BerriAI/litellm/pull/43586), merged 2026-09-28,
  at $2/$10. `gpt-6-luna` was added 2026-09-22
  ([LiteLLM blog](https://docs.litellm.ai/blog/gpt_6_sol_luna)) at the rates above. The
  conductor's read-only check (2026-09-30) confirmed upstream LiteLLM now carries the bare keys
  `claude-sonnet-5-5` and `gpt-6-luna`. The bundled entries use the same keys.
- **Live store (conductor read-only check, 2026-09-30).** In the live store, `claude-*` and
  `codex-*` records for these models are stored as `{basis:'unknown', status:'no_rate'}`.
  `antigravity-cli` rows are harness-priced. This confirms Defect B on real data and that U8
  leaves Antigravity figures alone.
- **GitHub Copilot** ([models-and-pricing](https://docs.github.com/copilot/reference/copilot-billing/models-and-pricing),
  no page date shown):
  - The table is **per 1M tokens** (Input / Cached input / Cache write / Output, with
    Tier/Threshold), not a per-request multiplier. "1 AI credit = $0.01 USD".
  - All three models are listed (GA). Their USD rates equal the vendor list prices above:
    Sonnet 5.5 is 200/20/250/1000 credits, Opus 5 is 500/50/625/2500, and GPT-6 Luna is
    10/1/n/a/50 (≤272K) and 20/2/n/a/75 (>272K).
- Confidence: high for Anthropic and Copilot, medium-high for OpenAI (the page was summarised by
  the fetch tool, and its long-context threshold comes from the Copilot page and LiteLLM), and
  high for the LiteLLM keys (conductor-verified).

Consequence for the Copilot table (U11 and design step 5). The Copilot table is a token-rate table with separate cache classes and an
input-size tier. The current `Rate` type (`cost.ts:35`, flat `inputRate`/`outputRate`) and
`priceWithTable` (`cost.ts:175`, cache charged at the full input rate) cannot express it. Design
step 5 therefore extends `Rate` with optional `cacheReadRate`/`cacheWriteRate` and optional
per-model `tiers`. An absent cache rate keeps today's full-input-rate arithmetic, so the existing
`cost.test.ts` / `cost.scoping.test.ts` expectations are unchanged.

## Design

### Phase 1: Defect A (bridge mapping + basis/status exposure)

1. `ParsedSummary.cost` (`bridge.ts:147`) is re-typed to the canonical `CostBlock` shape. Import
   `CostBlock` from `../canon/types.js` rather than restating it.
2. `SessionSummary` (`bridge.ts:84-102`) gains `cost: { basis: string; status: string; value?: number;
   currency?: string }`, which carries the writer's block (normalized, never invented).
   - `cost_usd` stays for its existing consumers (`tools/report-fixtures.ts`, API clients), but is
     derived honestly: the block's `value` only when `status === 'priced'` and
     `currency === 'USD'`, otherwise `null`.
   - A row with no summary cost gets `{basis:'unknown', status:'no_rate'}`.
   - The legacy `usd` read is dropped: the `session` table is a rebuildable cache over canonical
     records (`projection.ts:19-23`), and no canonical writer produces `usd`.
3. Web: `KyberSessionSummary` (`dash/web/src/lib/kyberApi.ts:62-86`) gains `cost?`.
   - `AgentSessionRow` renders the cell through `formatCostFigure(normalizeCostBlock(s.cost))`,
     imported from `SessionCostPanel.tsx`. A `title` names the basis (for example
     "published rate" or "harness-reported").
   - `—` remains only when the server sends no `cost` at all (an older server).
   - A partial session renders "partially priced" with no figure, exactly as the tile does (U10).

### Phase 2: Defect B (pricing)

4. **Published-table pricer for API-billed harnesses.** Add `pricePublishedTurn(tokens, model,
   harness)` to a new `dash/src/canon/published-pricing.ts`. It is kept out of
   `canon/cost.ts` so the pure engine stays independent of `pricing/`.
   - Check `check:reachable` and the diagnostic-cost import guard
     (`checkDiagnosticCostImports`) before choosing the file home.
   - Rules, in order:
     - A harness-reported figure is never touched (R5.2).
     - A harness outside `LITELLM_APPLICABILITY = ['claude-code', 'codex']`, compared after
       normalization, gets `{published, out_of_scope}` (R5.3).
     - No `getModelCosts` rate, or a stub rate with no billable cost, gets `{published, no_rate}`
       (R5.4).
     - A model in `flatRateModels` gets `{published, not_billed}` (R5.5).
     - Otherwise the result is `{published, priced, value: calculateCost(...), currency:'USD',
       byModel}`, with cache-aware classes taken from the canonical `TokenUsage`.
   - `priceOverrides` and `modelAliases` flow through `getModelCosts` unchanged (U4).
   - **Rate data (U11).** Add `claude-sonnet-5-5` (input 2.00, output 10.00, cache
     write 2.50, cache read 0.20 per 1M; flat) and `gpt-6-luna` (0.10 / 0.50, cache read 0.01;
     >272K tier 0.20 / 0.75 / 0.02) to the bundled pricing data.
     - Use the file and tier mechanism `models.ts` already reads for tiered models
       (`tieredCostsFor`). The implementer confirms whether that is `pricing-fallback.json` or a
       built-in table.
     - Record each entry's source URL and the 2026-09-30 retrieval in the data file's provenance.
       `pricing-fallback-data.test.ts` guards the file.
5. **Copilot credits table.**
   - Add `COPILOT_CREDITS_TABLE: RateTable` with `applicability: ['copilot']` (normalized
     `copilot-*`), `currency: 'USD'`, and a `publishedRates` map transcribed from the GitHub page
     for `claude-sonnet-5-5`, `claude-opus-5` and `gpt-6-luna` (values in "External rate facts").
     - The table carries its name, source URL, retrieval date (2026-09-30) and `credit_usd: 0.01`.
   - Extend `Rate` with optional `cacheReadRate` / `cacheWriteRate` and optional per-model
     `tiers`, and teach `priceWithTable` to price the disjoint classes: fresh × input,
     cacheRead × cacheReadRate, cacheCreation × cacheWriteRate, output × output.
     - A tier is chosen by measured input (R5.6).
     - An absent cache rate falls back to the input rate, which is today's arithmetic.
   - Price Copilot turns with `priceWithTable`.
   - LiteLLM-derived Copilot figures from the upstream parser (`providers/copilot.ts:999`,
     labelled `harness`) are **not** carried as `harness` basis. For the LiteLLM table they are
     `out_of_scope` (closes the latent R5.3 hazard).
     - A genuinely harness-reported Copilot figure (for example the `cost_usd` column read at
       `synth/readers/copilot.ts:89`) still wins (R5.2). The implementer distinguishes the two by
       provenance, not by value.
   - A Copilot model the table does not list is `{published, no_rate}`.
   - `getMeta().rates` (`bridge.ts:2233-2251`) describes both tables: source, retrieved date,
     applicability.
6. **Honest session totals.**
   - `buildSessionRow` sums the cost blocks of **turn records only** (`isTurn`). A non-turn span
     makes no cost claim.
   - An unpriced turn from a published-table attempt carries `basis:'published'`, so a
     partly-priced session totals `partial`, not a basis mismatch.
   - A genuine `COST_BASIS_MISMATCH` (harness and published turns in one session) is recorded in
     the payload's `problems`, where `SessionCostPanel` already reads it, instead of being
     silently replaced with `no_rate`.
   - `costBlockFor` (`synth.ts:306`) returns `{published, no_rate}` for a zero figure from a
     published-rate provider (`costIsEstimated: true`), and keeps `unknown` only for a source
     that makes no pricing attempt.
7. **Re-derivation (U9, no schema bump).** `buildSessions` reprices non-harness turn records
   through steps 4 and 5 and writes changed `cost_json` back before summing. Existing stores fix
   themselves on the next projection, and a `priceOverrides` change applies on the next projection.

## Risks

- **Silent R5.3 regression.** Adding models to the snapshot, or an override, must never price
  Copilot through LiteLLM. T5 and T7 pin this with explicit `copilot` + snapshot-model cases.
- **Totals shift for currently-priced harnesses.** The turn-only summation and the `published`
  basis for unpriced attempts change some sessions from `no_rate` to `partial`. That is intended
  and honest, and it is pinned by T9.
- **Projection cost (U9).** Repricing reads every turn record once per projection. The
  projection already loads every record in `buildSessions`. Write back only changed blocks, in the
  projection's transaction.
- **Live model-id variants.** The conductor confirmed the live store holds `claude-*` and
  `codex-*` records for these models as `{unknown,no_rate}`. Whether any records carry dated
  suffixes or `[1m]` variants was not separately enumerated. The alias path
  (`resolveCanonicalModelId`) covers known variants, and T6 evidence names any variant it meets.
- **Fixture migration.** Several tests encode the legacy `{usd}` shape. Migrating them is part
  of the contract (T1, T3), not a weakening.
- **Rate provenance.** The Copilot page shows no date, and the OpenAI figures came through a
  summarising fetch. T6/T8 evidence must quote the rate rows retrieved at implementation time,
  and any disagreement with "External rate facts" returns the plan to Draft.
- **Plan lifecycle.** Any change to U8–U12 or to the development mode returns the plan to Draft
  and reopens approval of the affected Test contract rows.
- **Engine change.** Extending `Rate`/`priceWithTable` touches the R5.x engine. The existing
  `cost.test.ts`, `cost.scoping.test.ts` and `data-handling.test.ts` must stay GREEN unchanged
  (absent cache rates reproduce today's arithmetic).
