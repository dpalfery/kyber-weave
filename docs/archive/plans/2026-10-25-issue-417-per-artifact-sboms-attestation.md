## 1. Problem and goal

### 1.1 Problem

#383/#416 shipped a single **aggregate** SBOM: one `kyber-weave-sbom-<version>.cdx.json` that
describes the repository's dependency closure across .NET, npm and Cargo, built by scanning the
checked-in lock files plus a throwaway framework-dependent `dotnet publish`. ADR 0042 decision 1
chose aggregate-over-per-artifact deliberately, and decision 7 records the honest gap: the
aggregate is an inventory of **build inputs**, not a byte-level statement about any archive.
In particular it does not list the .NET runtime embedded in the self-contained single-file CLI
and MCP binaries, nor the Node runtime embedded in the KyberDash single-executable, nor what is
inside the Squad bundles.

Issue #417 closes that gap: a **per-artifact** SBOM generated from the **published archive
bytes** (unpack each archive, scan the extracted tree with the same pinned Syft), one document
per artifact, each covered by `SHA256SUMS.txt`, and each covered by a verifiable GitHub
attestation.

### 1.2 Goal

1. **Per-artifact SBOMs.** Every published archive (20 today: 5 CLI, 5 MCP, 5 KyberDash,
   3 tray, 2 Squad) gets a corresponding CycloneDX 1.6 JSON document generated by unpacking the
   archive into a throwaway directory and scanning it with the same SHA-256-pinned Syft 1.55.0.
   One document per artifact, named `<archive-stem>.cdx.json` (e.g. `kyber-weave-linux-x64.cdx.json`).
2. **Manifest coverage.** Every per-artifact SBOM (and the aggregate) is a first-class release
   asset: listed in `scripts/verify-release-checksums.sh`'s `EXPECTED_ASSETS` and covered by
   `SHA256SUMS.txt`, so the existing fail-closed pre-publish check and the post-publish inventory
   check cover them.
3. **Attestation.** Every SBOM carries a verifiable GitHub attestation
   (`gh attestation verify` succeeds for a real release), generated by GitHub's SBOM-attestation
   action with `id-token: write` + `attestations: write` permissions.
4. **Honest docs.** `docs/install.md` and `docs/distribution.md` state what per-artifact SBOMs
   cover (byte-level file inventory of each archive) and what they still do not (the embedded
   runtimes), and ADR 0042 is amended / partly superseded with the new coverage contract.

### 1.3 Out of scope

- **Code signing / Authenticode.** Unchanged; still deferred (issue #132, ADR 0027).
- **Enumerating embedded runtimes as components.** A byte-level scan cannot recover the .NET
  runtime from a self-contained single-file binary or the Node runtime / embedded npm closure
  from a SEA blob. Per-artifact SBOMs record this as explicit `not-measured` metadata rather
  than pretending. (Decisions D3, D4.)
- **Test-only dependencies.** Still not part of any SBOM (unchanged from ADR 0042).
- **nuget.org as a distribution channel.** Still forbidden (ADR 0027); the generator remains a
  pinned, SHA-256-verified Syft tarball, never a `dotnet tool`.
- **`gh-packages` (PackAsTool).** Unaffected; no SBOM/attestation change there.

## 3. Investigation findings

### 3.1 Current aggregate path (read directly)

- **`scripts/generate-sbom.sh`** (754 lines) pins Syft `1.55.0` + four SHA-256 hashes, resolves it
  PATH → cache → download-and-verify (fail-closed), stages a framework-dependent non-single-file
  publish to recover `*.deps.json`, scans `dir:${REPO_ROOT}` with excludes, then normalises +
  dedupes + validates in one Python pass and finally validates against the vendored
  `scripts/schemas/` CycloneDX 1.6 schema. Output: `kyber-weave-sbom-<version>.cdx.json`.
- **`scripts/validate-sbom.py`** (503 lines) is a Draft-7 subset validator with
  `--require-ecosystems`/`--optional-ecosystems`; a no-components SBOM is an error (line ~472).
  Per-artifact SBOMs will call it **without** `--require-ecosystems` (a self-contained archive has
  no npm/cargo/nuget), relying on the file cataloger for non-empty output.
- **`scripts/verify-release-checksums.sh`** (221 lines) holds `EXPECTED_ASSETS` (21 entries) and is
  the authoritative pre-publish + post-publish list (via `--list`). It rejects missing *and*
  unexpected files, deletes stale `SHA256SUMS.txt`, and atomically writes the manifest.
- **`.github/workflows/release.yml`**: `sbom` job (lines 715–777) generates + validates + uploads the
  aggregate as artifact `sbom`. The `release` job (lines 779+) `needs:
  [version, build, build-kyberdash, build-tray, pack-squad, sbom]`, has `permissions: contents:
  write`, downloads all artifacts (`pattern: "*"`, merge), runs `verify-release-checksums.sh`, then
  `gh release create release-assets/*`, then post-publish verifies the asset set (via `--list`) and
  byte-compares the manifest. Build jobs upload artifacts named `binaries-<rid>`,
  `binaries-kyberdash-<rid>`, `squad-archives`, `tray-<rid>`, `sbom`.
- **`scripts/release-local.sh`** builds one RID's archives + the aggregate SBOM, then hashes `*` in
  the tree (it does not use `verify-release-checksums.sh`). Parity = also emit per-artifact SBOMs
  for the archives it produced.
- **Tests**: `tests/KyberWeave.Tests/ReleaseTests.cs` has `ReleaseAssets` (21 entries) + count-21
  assertions and workflow assertions (`needs` list, `--list` mode, step ordering).
  `tests/KyberWeave.Tests/SbomTests.cs` has the validator + workflow assertions
  (`TheReleaseWorkflowGeneratesTheSbomBeforeTheReleaseJob`, `TheExpectedReleaseAssetListCarriesTheSbom`).
- **Docs**: `docs/install.md#the-sbom-what-each-release-ships` and `docs/distribution.md#the-sbom-asset`
  describe the aggregate and its four coverage limits; `docs/adr/0042-…` decisions 1 and 7 and its
  "Alternatives" (per-artifact) are the records to amend.

### 3.2 Attestation facts (verified live)

- `actions/attest-sbom` is **deprecated** in favor of **`actions/attest`**; the unified action's SBOM
  mode is `sbom-path` + `subject-path` (SBOM = predicate, subject = artifact). Required permissions:
  `id-token: write`, `attestations: write`, `artifact-metadata: write` (plus `contents: read`).
- `gh attestation verify <file> --repo owner/repo --predicate-type https://cyclonedx.org/bom`
  verifies a CycloneDX SBOM attestation (confirmed against the GitHub CLI manual and worked examples).

### 3.3 Catalog

`component: Distribution` (source root `scripts`, docs `install.md` + `distribution.md`) is the
correct catalog component for this plan; `owner: dpalfery` exists.

## 7. Risks and out-of-scope boundaries

- **Sparse per-artifact SBOMs.** Self-contained single-file and SEA archives legitimately yield
  file-level + "not-measured" documents, not full component closures. This is stated in docs, not
  papered over (D3/D4). Risk of a reviewer misreading "SBOM per artifact" as "full closure per
  artifact" — mitigated by the ADR amendment and doc wording.
- **`actions/attest` vs the issue's `actions/attest-sbom`.** Deprecation deviation (D6) is recorded
  with reason; if the reviewer insists on the literal action, the wrapper is still available and the
  change is one line.
- **Attestation ordering.** `gh attestation verify` runs in the `release` job after `attest-sbom`
  persists attestations; a propagation lag is possible — the verify step should tolerate a short
  retry rather than fail hard on first read.
- **Asset-count churn.** 21→41 expected assets touches `verify-release-checksums.sh`, the count test,
  and `distribution.md` together; kept in one task (T3) so the three cannot drift.
- **CI unaffected.** Per-artifact generation is release-only; `generate-sbom.sh` keeps its interface,
  so the CI SBOM-validation job and its `needs.sbom.result` gate are untouched (D5 regression net).
- **Syft pin maintenance.** Still one place (`syft-bootstrap.sh`) — no second pin to drift.
