# Parse tool calls and results across session sources to activate KyberDash detectors (issue #180)

Archived 2026-09-30 at PR close; implementation complete, follow-up issues #210–#215 filed for deferred harnesses.

**Status: Complete**

Input: [GitHub issue #180](https://github.com/dpalfery/kyber-weave/issues/180) ("KyberDash: tool calls and tools offered are never reported, so 6 of 8 detectors never fire").

`development-mode: test-first`. Every implementation task in this plan defines a failing test contract before production code changes.

---

## 1. Problem and Goal

### 1.1 Problem Statement
Across hundreds of real-world sessions ingested by KyberDash (spanning Claude Code, Codex, Copilot, Cursor, Antigravity, ZCode, and OpenCode), KyberDash consistently displays:
- **Tool calls**: `—` (tooltip: `"Tool invocation count was not reported by <harness>"`).
- **Tools offered**: `—` (tooltip: `"Tool definitions were not exported by <harness>"`).
- **Scorecard dimension `tool_yield`**: `not measurable` across all harnesses.
- **Finding detectors**: 6 of 8 detectors never fire (`duplicate-tool-call` [except on Copilot OTel traces], `oversized-tool-result`, `dormant-tool-schema`, `inactive-skill-reference`, `unbounded-delegation`, and `prefix-cache-break`).
- **Timeline / Call Tree**: Renders only top-level `llm.invoke` spans (`internal ... 0ms no_rate`), with zero child spans for tool executions or command outputs.

### 1.2 Concrete Audit Evidence
- In an audit of a 73-turn Claude Code session with 179 tool executions (`Bash`, `Read`, `Grep`, `Edit`, `Glob`), KyberDash reported 0 tool calls, 0 tools offered, and 0 findings.
- In Copilot CLI and VS Code sessions, tool requests and tool calls were present in the transcript JSON but completely omitted from the session report.
- In Codex transcripts, tool call blocks (`function_call`, `custom_tool_call`) were explicitly discarded with a code comment `// Deliberately dropped`.

### 1.3 Goal
After executing this plan:
1. The Claude Code transcript parser extracts tool invocations (with names and arguments) and tool results (with execution status and bound payload content).
2. The `Synthesizer` emits child `CanonicalRecord` instances with `op: 'tool.invoke'`, `parentSpanId` linked to the turn/LLM span, tool arguments in `raw`, and bounded tool output in `parts` (`part: 'tool_result_content'`).
3. `buildSessionRow` computes and emits `summary.tool_calls`, `summary.tools_invoked`, and `summary.tools_offered`.
4. The starved finding detectors fire on synthetic and real session transcripts when defects are present.
5. KyberDash Overview cards, Timeline call trees, and Scorecard `tool_yield` metrics render accurate counts.
6. Checkpoint invalidation via `parser_contract_version` ensures existing ingested sessions are re-synthesized upon `refresh`.

### 2.2 Decision on Open Question 1: No Harness Profile Tool Defaulting (Honest Unobservability)
- **Decision**: **DO NOT** infer or default `tools_offered` from a static harness profile or preset list.
- **Rationale**: Fabricated data is strictly prohibited by [rules/honest-unobservability.md](../../rules/honest-unobservability.md). If a harness transcript or telemetry stream does not explicitly disclose the tool schemas offered to the model, `tools_offered` remains unmeasured. KyberDash will continue rendering `—` with the honest tooltip `"Tool definitions were not exported by <harness>"` and `tool_yield` as `not measurable`. Only telemetry-grounded tool declarations will be recorded as offered tools.

### 2.3 Decision on Open Question 2: Subagent Tool Invocations Deferred
- **Decision**: Nested subagent tool invocations (such as background `Task` subagent tool calls) are out of scope for this slice.
- **Rationale**: Subagents introduce multi-session correlation and child trace hierarchies that warrant dedicated design. In this slice, `Task` invocations are treated as standard top-level tool calls. Full child subagent span nesting is deferred.

### 2.4 Decision on Open Question 3: Structured Error Signals Only (No Regex Guessing)
- **Decision**: Tool execution status (`ok` vs `error`) must be determined strictly from structured metadata signals:
  1. `is_error === true` on the tool result object.
  2. Non-zero exit code (`exit_code !== 0`) when provided in structured execution output.
- **Constraint**: Heuristic regex scanning of tool output text (e.g., searching for `"error"`, `"exception"`, or `"failed"`) is prohibited. Output text often contains false positives (e.g. grep matches or compiler warnings).

### 2.5 Parser Contract Version & Refresh Invalidation
- **Decision**: Bump `PARSER_CONTRACT_VERSION` in `dash/src/refresh/registry.ts` (e.g., from `'1'` to `'2'`) for every source whose parsing output changes.
- **Rationale**: Checkpoints stored in `source_checkpoint` record `parser_contract_version`. When the contract version is incremented, `kyber-weave dash refresh` recognizes that existing checkpoints are stale and triggers re-synthesis from source transcripts, automatically backpopulating tool calls into legacy sessions without requiring manual database deletion.
- **Verification Requirement**: Add an automated test proving stale checkpoints are re-read and re-synthesized when `parser_contract_version` changes.

### 2.6 Bound Stored Tool Results
- **Decision**: Tool result content stored in `parts` (`part: 'tool_result_content'`) is bounded to **64KB per result**.
- **Payload Attribute**: Whenever truncation occurs:
  - The content text is truncated at 64KB with an explicit truncation indicator.
  - The part retains `truncated: true`.
  - The canonical record attributes record the original byte length in `attributes['gen_ai.tool.result_bytes']`.
- **Rationale**: Prevents database and memory bloat from multi-megabyte command outputs while preserving exact payload size telemetry for detectors such as `oversized-tool-result`.

## 3. Root Cause Analysis (File & Line Evidence)

### 3.1 Root Cause A: Missing `tool_calls`, `tools_invoked`, and `tools_offered` in Session Summary
- **Evidence**: `dash/src/canon/sessions.ts:509-520`
  `buildSessionRow` builds `payload.summary`, but populates only `turn_count`, `request_count`, `total_input`, `total_output`, `total_cache_read`, `total_cache_creation`, `duration_ms`, `models`, and `cost`. It never sets `tool_calls`, `tools_invoked`, or `tools_offered`.
- **UI Impact**: `dash/web/src/components/AgentSessionDashboard.tsx:623-625, 1011-1044`
  The Overview card checks `typeof u.tool_calls === 'number' && Number.isFinite(u.tool_calls)`. Because `u.tool_calls` is undefined, `toolCallsMeasured` is `false`, displaying `—` with tooltip `"Tool invocation count was not reported by <harness>"`, and `tools_offered` displays `—` with `"not exported by <harness>"`.

### 3.2 Root Cause B: Synthesizer Never Emits `op: 'tool.invoke'` Canonical Records
- **Evidence**: `dash/src/synth/synth.ts:323-337, 376-377, 455-472`
  `Synthesizer.synthesize` and `synthesizeEnvelopes` only call `synthesizeCall`, which hardcodes `op: 'llm.invoke'`. It never synthesizes child `CanonicalRecord`s for tool calls.
- **Evidence**: `dash/src/canon/sessions.ts:184-188`
  `invocationsOf(records)` is defined strictly as:
  ```ts
  records.filter((record) => record.op === 'tool.invoke')
         .map((record) => attributeOf(record, ['gen_ai.tool.name']) ?? record.name)
  ```
  Because no `tool.invoke` records exist for any session-file harness, `invocationsOf(records)` returns `[]`, `invocationCounts` is empty, and `tools` resident array has `invocations: 0`.
- **Evidence**: `dash/src/analysis/timeline.ts:167-207`
  Timeline nodes are built directly from `CanonicalRecord`s. With only `llm.invoke` root spans and zero child spans, call-tree rows render only `internal ... 0ms no_rate`.

### 3.3 Root Cause C: 6 of 8 Finding Detectors Starved of Tool Spans
- `detectDuplicateToolCall` (`dash/src/analysis/findings.ts:507-521`): Only checks `r.op === 'tool.invoke'`. It fired 49 times on Copilot exclusively because Copilot had OTel trace spans containing `execute_tool` / `gen_ai.tool.name`. For all other harnesses, it never received any records.
- `detectOversizedToolResult` (`dash/src/analysis/findings.ts:655-670`): Checks `r.op === 'tool.invoke'` for `part === 'tool_result_content'` or `r.raw.result`. Zero `tool.invoke` spans means 0 detections.
- `detectDormantToolSchema` (`dash/src/analysis/findings.ts:358-360, 393-400`): Checks `toolRecords = records.filter(r => r.op === 'tool.invoke')`. Without tool invocations and resident tool definition parts, it never flags dormant tools.
- `detectInactiveSkillReference` (`dash/src/analysis/findings.ts:1253`): Checks `toolRecords = records.filter(r => r.op === 'tool.invoke')`.
- `detectUnboundedDelegation` (`dash/src/analysis/findings.ts:1152-1165`): Relies on subagent tool execution evidence.
- `detectPrefixCacheBreak` (`dash/src/analysis/findings.ts:801-815`): Requires `system_prompt` / `instruction_context` parts.

### 3.4 Root Cause D: Transcript Readers Drop `tool_use` and `tool_result` Across Harnesses
- **Claude** (`dash/src/synth/readers/claude.ts:152-153, 283-350`; `dash/src/providers/claude.ts:400`):
  `loadClaudeCalls` hardcodes `tools: [], bashCommands: []`. `readClaudeSession` processes `text`, `thinking`, `tool_result`, but completely ignores `block.type === 'tool_use'`. Claude's `createSessionParser` is empty. The audit transcript's 179 `tool_use` blocks are dropped.
- **Codex** (`dash/src/synth/readers/codex.ts:271-272`):
  `codexReader.read` explicitly drops `function_call` and `custom_tool_call` (`// Deliberately dropped`).
- **Copilot** (`dash/src/synth/readers/copilot.ts:90-91`; `dash/src/synth/readers/copilot-vscode.ts:80-114`):
  `loadCopilotCliCalls` hardcodes `tools: []`. `copilotVscodeReader` ignores `toolRequests` and `toolCalls`.
- **Cursor** (`dash/src/synth/readers/cursor.ts:79-100`):
  `cursorReader` does not emit tool calls or tool results into `ReaderTurn.parts`.
- **Antigravity** (`dash/src/providers/antigravity.ts:859, 1001, 1226`):
  Hardcodes `tools: [], bashCommands: []` in all 3 generator metadata / SQLite builders.
- **ZCode** (`dash/src/providers/zcode.ts:119-130`):
  Extracts tool names from `tool_usage`, but does not create `toolSequence` or tool records with arguments/duration.
- **OpenCode** (`dash/src/synth/readers/opencode.ts:14-18`):
  `opencodeReader` is an empty stub (`async *read(): AsyncGenerator<never>`).

### 3.5 Root Cause E: Scorecard Dimension Availability
- `tool_yield` in `dash/src/canon/harnesses.ts:286-305` calculates `totalInvokedTools / totalDefinedTools` from `payload.tools` or `payload.servers`. Because `payload.tools` was empty or `invocations` was 0, `toolYield` defaults to null / `notMeasurable`.
- `skill_utilisation` and `continuity` are currently flagged `not_measurable` in `HarnessDetail.tsx:135, 154` due to lack of recorded tool activation and correction turns.

## 4. Architecture & Data Flow Design

### 4.1 Data Flow Overview
```
+--------------------------------------------------------------------------------+
| Transcripts (Claude .jsonl sessions)                                           |
+--------------------------------------------------------------------------------+
                                       |
                                       v
+--------------------------------------------------------------------------------+
| Harness Readers (dash/src/synth/readers/claude.ts, dash/src/providers/claude.ts)|
| - Extract tool declarations if present                                         |
| - Extract tool invocations (id, name, args, start timestamp)                   |
| - Extract tool results (tool_use_id, result text, is_error status)             |
+--------------------------------------------------------------------------------+
                                       | ReaderTurn with toolCalls, toolResults
                                       v
+--------------------------------------------------------------------------------+
| Synthesizer (dash/src/synth/synth.ts)                                          |
| - Creates Turn record (op: 'llm.invoke')                                       |
| - Creates Child records (op: 'tool.invoke')                                    |
|   * parentSpanId: turnRecord.spanId                                            |
|   * attributes: { 'gen_ai.tool.name', 'gen_ai.tool.status', 'gen_ai.tool.result_bytes' } |
|   * raw: { arguments: string, result: string, durationMs: number }             |
|   * parts: [{ part: 'tool_result_content', text: boundedText, truncated: bool }|
+--------------------------------------------------------------------------------+
                                       | CanonicalRecord[] (llm.invoke + tool.invoke)
                                       v
+--------------------------------------------------------------------------------+
| Session Projection (dash/src/canon/sessions.ts)                                |
| - buildSessionRow:                                                             |
|   * summary.tool_calls = records.filter(r => r.op === 'tool.invoke').length   |
|   * summary.tools_invoked = invocationsOf(records)                             |
|   * summary.tools_offered = extractOfferedTools(records, metadata)             |
|   * payload.tools = [{ name, invocations, errors, duration_ms }]               |
+--------------------------------------------------------------------------------+
                                       |
          +----------------------------+----------------------------+
          |                                                         |
          v                                                         v
+------------------------------------+     +------------------------------------+
| Finding Detectors                  |     | KyberDash UI                       |
| (dash/src/analysis/findings.ts)    |     | (dash/web/src/components/*)        |
| - duplicate-tool-call fires        |     | - Overview card: tool count & yield|
| - oversized-tool-result fires      |     | - Timeline: expandable tool trees  |
| - dormant-tool-schema fires        |     | - Scorecard: tool_yield measured   |
+------------------------------------+     +------------------------------------+
```

### 4.2 Canonical Representation Contracts
1. **Reader Turn Types** (`dash/src/synth/readers/types.ts`):
   ```ts
   export interface ReaderToolCall {
     id: string;
     name: string;
     arguments: Record<string, unknown> | string;
     timestamp?: string;
     durationMs?: number;
   }

   export interface ReaderToolResult {
     toolCallId: string;
     name?: string;
     content: string;
     isError?: boolean;
     timestamp?: string;
   }

   export interface ReaderTurn {
     turnId?: string;
     model?: string;
     // ... existing fields ...
     toolCalls?: ReaderToolCall[];
     toolResults?: ReaderToolResult[];
     toolsOffered?: string[];
   }
   ```

2. **Canonical Record Structure for Tool Invocations**:
   - `record.op`: `'tool.invoke'`
   - `record.name`: tool name (e.g. `'Bash'`, `'Read'`, `'Edit'`, `'Grep'`)
   - `record.spanId`: deterministic hex span id (`${turnSpanId}-t${toolIndex}`)
   - `record.parentSpanId`: turn span id
   - `record.attributes`:
     - `'gen_ai.tool.name'`: tool name
     - `'gen_ai.tool.call_id'`: tool call id
     - `'gen_ai.tool.status'`: `'ok'` | `'error'` | `'unset'` (derived strictly from `is_error` or exit code, or `'unset'` when unmeasured)
     - `'gen_ai.tool.result_bytes'`: original unclipped byte length
   - `record.raw`: `{ arguments: toolCall.arguments, result: pairedResult?.content }`
   - `record.parts`: `[{ part: 'tool_result_content', text: truncateToolContent(pairedResult?.content, 64 * 1024), truncated: boolean }]`

## 6. Risks and Mitigations

| Risk | Impact | Mitigation Strategy |
|---|---|---|
| **Memory / DB Bloat from Tool Outputs** | Transcript tool results can include multi-megabyte grep outputs or file reads. Storing raw megabytes in `parts` could explode `canon.db` size. | Truncate `tool_result_content` at content-part level (max 64KB per output) with `truncated: true`. Record the full raw byte length in `attributes['gen_ai.tool.result_bytes']` so detectors like `oversized-tool-result` can evaluate actual payload sizes without blowing up memory. |
| **Missing Timestamps in Transcripts** | Some transcript formats record tool invocations but omit per-tool execution start/end timestamps. | Fall back to attributing tool start time to the parent turn timestamp and setting duration to 0ms (or interpolating evenly across the turn duration) to avoid NaN or invalid timeline ranges. |
| **Span ID Collision** | Generating synthetic child span IDs from turn IDs could collide if multiple tools have identical names in one turn. | Use indexed deterministic span IDs: `${turnRecord.spanId}-t${toolIndex}`. |
| **Backward Compatibility & Cache Invalidation** | Existing `canon.db` files ingested under prior versions do not have `tool.invoke` records. | Bumping `PARSER_CONTRACT_VERSION` in `dash/src/refresh/registry.ts` causes `kyber-weave dash refresh` to recognize stale checkpoints and cleanly re-synthesize old sessions from source transcripts. ## 8. Open Questions & Recorded Decisions

1. **Q: Should tool definitions (tools offered) be inferred if a transcript does not list schema declarations?**
   - **Decision**: **NO**. If the transcript does not explicitly declare tool definitions, do not invent them. In accordance with [rules/honest-unobservability.md](../../rules/honest-unobservability.md), leave `tools_offered` unmeasured (`—`). Fabricated data is prohibited.

2. **Q: Should subagent tool invocations (e.g., Task subagents) be represented as separate turns or nested tool spans?**
   - **Decision**: Subagent span nesting is **deferred** from this slice. `Task` executions are recorded as standard top-level tool invocations for now.

3. **Q: How should error results in tool executions be standardized across harnesses?**
   - **Decision**: Standardize `attributes['gen_ai.tool.status'] = 'error'` strictly from structured error flags (`is_error === true` or non-zero exit code). Do not use heuristic regex parsing of free-form output text.
