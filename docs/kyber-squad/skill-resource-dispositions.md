# Skill-resource dispositions and policy-line ledger

This reference is the content-preservation audit for the supplemental files that sit
beside the canonical `SKILL.md` files under `products/kyber-squad/skills/`. It exists so
that, for every one of those resources, a reader can answer three questions: what kind of
content it is, what happens to it, and — where it states a rule a host could reverse — where
that rule now lives. It is a governed `reference` document (D5) and it outlives the plan that
created it,
[`2026-09-28-skill-resource-dispositions.md`](../archive/plans/2026-09-28-skill-resource-dispositions.md).

**D2 — a skill's own directory is a durable home, except for a technology.** Review lenses,
product-owner phase references, PR provider files and scripts, the setup inventory, and
`setup-dev-environment/agents/openai.yaml` stay where they are, with a recorded reason: they
are procedure for a role or a tool, not how a technology is written. A **technology skill is
not a home** (owner decision, 2026-11-22): the per-technology skills `csharp-dev`, `dal-dev`,
`maui-dev`, `typescript-dev`, `rust-dev`, `python-dev`, `go-dev`, `github-devops` and
`csp-security` were deleted, and Squad no longer ships them. Every rule, framework-correctness
fact, security floor and procedure they held moved into the matching folder of the shipped
standards templates under `products/kyber-squad/standards/` — prohibitions to
`<tech>.rules.md`, commands and procedure to `<tech>.skills.md`, everything else to a `###`
section of `<tech>.standards.md` — which a worker receives through
`docs_get_coding_standard_for_technology`. A new technology gets a standards folder, never a
skill. The rows below marked `removed-with-skill` record where each deleted file's content went.

**Classification rule, in brief.** A line is **policy** — a stack, library, naming, layout, or
required-practice choice a host could reasonably reverse — when the matching
`standards/<tech>/<tech>.standards.md` template either already states it (`duplicate`, pointer added) or
lacks it (`migrated`, added to the template). A line is **technique** when it is a
framework-correctness fact, a security floor, or a how-to whose violation is a defect no
matter what the host prefers; in a technology skill it moved to the template with the policy,
and in any other skill it stays in the skill. A line that names a project fact or one
host's taste — a project name, a version, a wrapper class, an agent name, a tuning constant,
"do not add Scalar" — is `superseded`: removed from the skill and recorded here, never added
to a template (D4); so is a line that only restates a vendor's own documentation. Only the
technology-skill and test-dev references may carry a `migrated`, `duplicate`, or `superseded`
ledger row; a policy-looking line found elsewhere is `retained` with a reason.

**Delivery.** `squad install` and `squad pack` render every file that some Markdown link chain,
starting at a skill's own `SKILL.md`, actually reaches — a file named only in a code span is
packaged into both archives but never rendered beside its principal. Every resource below
that still ships is `rendered` except `skills/setup-dev-environment/agents/openai.yaml`, which is `packaged-only`
Codex skill-UI metadata that no instruction links to, and which stays that way by design (D6).
The four technology checklists (`go.md`, `rust.md`, `tauri.md`, `typescript.md`) are `rendered`
because `skills/code-review/SKILL.md` links them under Technology checklists.

**Records, not guidance.** Rows that cite a deleted technology skill's file are records of
wording that file held; the file no longer exists, and the rule lives where its row's
`Destination` says. The Policy-line ledger below quotes verbatim excerpts from the
resource files so that later edits can be checked against them (A5). A `migrated`,
`duplicate`, or `superseded` excerpt is a record of wording that is being removed or replaced,
not an instruction to follow — an agent resolving one of these skills should read the file as
it stands, not this ledger's quotations of what it used to say.
