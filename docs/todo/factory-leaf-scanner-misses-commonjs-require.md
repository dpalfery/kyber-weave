# The Factory leaf scanner does not see a CommonJS require

The rule that the Factory capture plugin's modules stay leaves — a module may not value-import
engine or plugin code — is checked by scanning their source
(`dash/src/architecture/factory-leaves.test.ts`). The scanner walks the syntax tree and classifies
three constructs: an `import` declaration, an `export … from` declaration, and a dynamic
`import()` call. Every other way of pulling in a module is invisible to it.

A CommonJS `require('…')` call is one of those ways. It is a call expression, not an import
declaration, so a leaf module that reaches engine code through `require` passes the scan. The
bundled plugin is committed text regenerated by esbuild and drift-checked, so the bundle is
whatever the source says it is; a `require` that the scan does not see is a `require` the bundle
carries.

The scanner's own cases cover a third-party package, a relative import outside the capture
family, a value import of the OpenCode plugin, a dynamic `import()`, and the `import type` escape.
None of them is a `require`, so the gap is not visible from the tests either.

**What a decision must settle.** Whether the rule should cover `require`, and what the scan should
look for:

- Extend the scanner to classify a `require('…')` call with a string literal the same way it
  classifies an `import` declaration, and add the case to its own tests. This is the smallest
  change and makes the rule say what it means.
- Reject `require` outright in a leaf, whatever it loads — a leaf is ESM, and a CommonJS call in
  an ESM module is a smell worth naming. That is a stricter rule than the current one and needs
  its own wording.
- Leave the scan as it is, on the grounds that the plugin's source is ESM and a `require` would
  not survive the build. That holds only if the bundle step would fail on it, which is worth
  confirming before it is relied on.

**Deliberately not done here.** The scanner was not changed. The rule's stated purpose — a leaf
that imports engine code drags the whole engine into a plugin that has to run as a small, bounded,
one-shot process — is unaffected by the gap in the moment, because no leaf module uses `require`
today. The gap is recorded because the scanner is the thing that keeps the rule true, and a rule
enforced by a scanner with a hole in it is not yet a rule.
