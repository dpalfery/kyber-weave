# KyberDash Copilot Baseline and Cross-Harness Full-Content Playwright Parity Suite

**Status: Draft.**

## Request

> lets opporate in suporvisory mode for this run, i want to review and approve the plan. the copilot harness properly displays in kyberdash, but many of the other harness runs do not, can we create a base line off the copilot runs in the current database and create playwrite tests that show where the other harnesses are not either collecting or displaying the full content in kyberdash?

## Problem and goal

KyberDash's existing Playwright suites (`dash/e2e/file-harness-dashboard.spec.ts`, `dash/e2e/otel-web-dashboard.spec.ts`, `dash/e2e/harness-collection.spec.ts`) verify summary cards, charts, timeline nodes, schema cost rankings, and session-level `StoredFieldsPanel` metadata, but **never verify whether full session content is collected, projected into turns, or rendered on screen** (prompts in `SessionRequestsSection`, unclipped blocks in `SessionInspectorDrawer` / `TurnFullContentPanel`, `/session/:id/turn/:index` `ContextInspector`, tool invocation inputs/results via `SessionTimelineSection` `tool.invoke` span inspection / `TurnFullContentPanel` `tool_result_content` / `StoredFieldsPanel` `tool_call` rows, tool definitions in `SessionToolsSection`, or `content_part` / `tool_call` / `tool_definition` stored-field tables). Because synthetic E2E fixtures also omit several telemetry shapes seen in real stores, regressions and missing content across harnesses go undetected.

Read-only aggregate inspection of the current live database (`~/.kyberdash/canon.db`, schema version `30`, detector version `8`, captured `2026-11-26T15:46:35Z`–`15:49:31Z`) establishes why Copilot currently displays more reliably than other harnesses — and also reveals gaps inside Copilot itself:

- **Copilot (`copilot`, OTLP source, `3` sessions / `3` runs / `316` records at snapshot start):** `100%` of sessions project (`3/3`), `100%` have measured context (`118/118` `llm.invoke` spans projected to `session_context_turn` and `session_turn`), `100%` have measured tool-definition schema (`1,090` `tool_definition` rows), `100%` carry `record_token_count` (`input`, `cache_read`, `output`), `system_prompt` carries forward across all `118` turns with non-empty `content_part_text` (`25/25`), `183–184/183–184` `tool.invoke` spans have `tool_call` rows, `16` skill invocations are stored, and both `cache_hit_rate` (`0.9172`) and `tool_yield` (`0.0747`) compute. At the same time, Copilot itself drops or withholds fields: `193/205` `conversation_history` parts and `183/183` `tool_result_content` parts sit in `content_part_withheld` with empty `part_text` (`ToTurnContentEntry` returns `""` to the UI), `23/25` `system_prompt` rows truncate at `65,536` bytes, `tool_call_input_text` / `tool_call_result_text` / `tool_call_mcp` are empty, only `6` `session_request` rows exist for `118` turns, and `copilot-cli` / `copilot-vscode` have `0` rows in `~/.kyberdash/canon.db`.
- **Other harnesses in `~/.kyberdash/canon.db`:**
  - `droid` (`4` sessions: `3` file + `1` OTLP): `0/3` projected sessions have `session_context` (`no_message_structure`), `0/3` have `session_schema` (`0` `tool_definition` rows), `0/251` records carry `record_token_count`, `1` session is unlinked, and `78` `llm.invoke` spans collapse into only `4` `session_turn` rows despite `47` `conversation_history`, `48` `reasoning`, and `74` `user_message` parts (`64` empty).
  - `claude-code` (`23` sessions: `21` file + `1` OTLP): `1` session is unprojected (`22` projected), only `761/1,037` `llm.invoke` spans (`73.4%`) produce `session_context_turn` rows, `0` `system_prompt` bucket parts exist (system text sits in `conversation_history` with role `system`, `13` withheld/truncated), `3` sessions lack schema data, `112/978` `tool.invoke` spans lack `tool_call` rows, and `tool_call_input_text` is `0`.
  - `antigravity` (`2` OTLP sessions): `1/2` sessions fail `context_unmeasurable` (`no_message_structure`), `0` `tool.invoke` spans / `0` `tool_call` rows (`tool_yield = 0.0`), `0` skills, `0` `session_title`/`session_workspace`, and `0` `content_part_role` rows.
  - `cursor` (`6` `CURSOR_WORKSPACE_UNREADABLE`), `devin` (`5` `DEVIN_SESSION_UNREADABLE`), `warp` (`1` `SQLITE_SOURCE_UNREADABLE`), `zcode` (`1` `SOURCE_FORMAT_UNEVIDENCED`): `0` sessions collected due to ingest errors/warnings, alongside `2,722` `unclaimed` quarantined spans and `75` `OTLP_LOG_UNATTRIBUTED` errors.

**Goal:** Codify a sanitized, version-pinned Copilot collection-and-display baseline contract derived from the current `~/.kyberdash/canon.db` snapshot (`schema_version=30`) and `CopilotCliMapper` contract, then build an isolated Playwright parity suite (`dash/e2e/harness-content-parity.spec.ts`) plus UI inspection assertions in `dash/e2e/session-dashboard-assertions.ts` that pinpoint — layer by layer (ingest/collection, projection, API, and UI render) — where every other supported harness across `HarnessSourceRegistry` and `dash/e2e/` (`24` registry entries + OTLP `codex` = `25` canonical IDs; `22` HTTP-testable harnesses) fails to collect or display full content in KyberDash.

### 3. Why existing Playwright tests missed collection and full-content display gaps
